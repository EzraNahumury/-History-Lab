# History Lab — Run & Test

> Full project docs (architecture, diagrams, judging map) live in the repo-root `README.md`.
> This file is the quick "how do I run it" for the `history-lab/` build.

## TL;DR — it runs offline, today, with no Anna account

The app ships with **Mock mode ON by default**, so the *entire* loop
(scene → choose → Historian's Ruling → **Approve / Flag** → accuracy → storybook)
is deterministic and playable with zero quota and no login.

```bash
npm i -g @anna-ai/cli          # once (needs Node 22+)
cd history-lab
anna-app validate --strict     # confirm ui.host_api covers every anna.<ns>.<method>
anna-app dev                   # dashboard at http://127.0.0.1:5180/
```

Then `#`-mention the app (or open its window from the dev dashboard) and play.

## Two modes

| Mode | How | What happens |
|---|---|---|
| **Mock** (default) | "Mock mode" checkbox **checked** | Scene + ruling come from the grounded `scenarios.js`. Fully deterministic — use this for the **stage demo**. |
| **Live** | uncheck "Mock mode" | Scene + ruling are generated by `anna.agent.session` (stream) → `anna.llm.complete` (fallback). Needs a real Nexus / auth, or `anna-app dev --mock-llm fixtures/cuban-missile.jsonl`. |

The app **degrades automatically**: if a live call fails or won't parse, it falls back to the
scripted content, so the demo never breaks mid-run.

## Day-1 Go/No-Go (do this first)

Before trusting Live mode, prove the agent path in the harness (see root `README.md` →
"Day-1 Go / No-Go spikes", or use `../spike-harness.html`). If `agent.session` streaming
won't parse, ship the demo in **Mock mode** — it's a complete, honest, grounded experience.

## File map

```
manifest.json      schema-2 manifest (ui.host_api allowlist, csp_overrides, dev block)
app.json           store listing metadata
bundle/            the static-spa SPA (no build step, no CDNs)
  index.html       entry (loads ./app.js as a module)
  styles.css
  sdk.js           connect() + host API handle (MATCH the import path to the scaffold)
  store.js         storage.get/set with etag + in-memory fallback
  agent.js         agent.session stream -> llm.complete -> scripted (graceful degradation)
  image.js         image.generate, DISPLAY-only (no fetch -> no CORS trap)
  scenarios.js     grounded Cuban Missile Crisis content (mock source)
  ui.js            DOM rendering (CSP-safe: no inline handlers/styles)
  app.js           orchestrator + turn state machine + human-review gate
scenarios/         canonical scenario JSON (docs/seed)
skills/historian-gm/SKILL.md   steers the agent's grounding + ruling format (should-have)
executas/history-lab-ledger/   optional deterministic commit tool (should-have)
fixtures/          optional --mock-llm fixture (the built-in Mock mode is the real safety net)
```

## Known things to verify in the harness (assumptions to confirm)

1. **SDK import path** in `bundle/sdk.js` matches what `anna-app dev` serves.
2. **`agent.session`** surface: `session({submode}).run({content})` vs `session.create/run`
   — `agent.js` handles both; confirm which fires.
3. **`storage.set`** arg shape (`{key,value,if_match}`) and the `precondition_failed` code.
4. **`chat.append_artifact`** renders at least a card; inline rendering is not assumed.
5. **`csp_overrides.img-src`** lets generated `<img>` URLs display in Live mode.
6. **Manifest field shapes** (`ui.views`, `default_size`) — if `extra='forbid'` rejects a
   field, copy the exact shape from a fresh `anna-app init` and re-add the `host_api` block.
